# Decision: arXiv 论文采集与摘要排序详细设计

Status: proposed

产品范围已确认；本文的页面布局、模块划分和未另行指定的数值为设计默认值。功能尚未实现，本文不表示现有应用已经具备所述能力。

## Problem

需要在阅读器内按关键词、作者和研究主题建立采集任务，完成论文发现、摘要分析、人工选择、PDF 下载和书架入库。使用者更关注减少漏检，需要查看原始资料、发现条件和排序依据。首次只发现最近 30 天的论文无法建立覆盖过去 12 个月的高被引列表，两种时间范围必须分别采集。

### 已确认范围

| 项目 | 要求 |
| --- | --- |
| 使用平台 | Windows 优先；应用运行期间定时采集，支持手动运行 |
| 论文来源 | 第一版只通过 arXiv 发现和下载论文，接受预印本 |
| 引用统计 | 允许额外服务补充统计；失败不阻止论文展示 |
| 最新相关 | 首次默认最近 30 天，可调整；之后追踪新增 |
| 近期高被引 | 独立分批回溯过去 12 个月，可调整；定期刷新引用统计 |
| 研究优先级 | 视觉方法、工业视觉应用、通用深度学习方法、材料预测、网络与边缘计算 |
| 作者关注 | 独立发现渠道，不受主题关键词限制；AI 主要帮助排序 |
| 原始资料 | 标题、作者、日期、摘要、来源、全文链接；提供中文翻译 |
| 可解释性 | 命中任务与条件、摘要相关性及其依据、统计来源与更新时间 |
| 分析额度 | 默认每日自动分析 100 篇，可调整；缓存结果，超额候选保留为待分析 |
| 入库方式 | 用户勾选后才下载并入库 |
| 后续范围 | 全文方法、实验和局限解读；近期新增引用趋势 |

## Proposal

### 1. 页面与用户流程

Windows 桌面导航新增“论文”。其他平台第一版不启动采集调度器、不显示新增入口，既有书架 PDF 阅读保持可用。共享源码仍须通过其他平台的静态检查。

论文页顶部展示任务筛选、搜索、运行状态、“运行任务”和“新建任务”。内容区提供“最新相关”“近期高被引”“任务”三个视图；待分析、低相关性、已忽略、已入库作为筛选条件。第一版采集任务、候选、分析缓存与运行记录仅保存在本机，页面设置说明这一同步范围。

| 视图 | 默认内容与操作 |
| --- | --- |
| 最新相关 | 显示首次提交日期位于当前最新窗口内的候选，默认按相关性排序；可切换最新发布时间排序 |
| 近期高被引 | 显示首次提交日期位于热门窗口内的候选，默认按累计引用次数排序；可切换相关性排序 |
| 任务 | 显示任务开关、频率、两种窗口的回溯进度、最近运行、错误和下一次执行时间 |
| 论文详情 | 原始标题与摘要、中文翻译、作者、分类、首次提交与版本更新时间、发表信息、两个来源的链接及发现记录 |
| 下载队列 | 每篇显示下载、等待入库、入库结果、失败原因；支持取消和重试，不把单篇失败扩散到整批 |

宽屏使用列表与详情分栏；窄窗口使用列表和独立详情页。候选行显示标题、作者摘要、首次提交日期、主题、相关性、引用次数、待分析/统计未知/已入库状态。批量勾选后出现“下载并加入书架”，明确数量。第一页默认 50 条；列表分页只影响渲染，不能限制采集或删除结果。

首次没有任务时提供五个可编辑模板，选择并保存启用后才开始采集。没有 AI 配置时仍可创建任务、采集原始资料、查看引用和下载，翻译与相关性显示待配置。没有引用数据时显示候选，并提示“引用统计待补充”。

详情中的“发现依据”列出每个任务及其查询修订、实际查询、时间范围、来源返回时间、命中分支和本地可核对的词句。来源返回但本地无法确认具体词句时，写“来源检索返回”，不编造精确命中解释。

“相关性依据”显示中文简述、对应英文摘要片段、任务主题、使用模型、分析时间和“基于摘要”的标记。低分结果默认收起在普通列表之外，但候选总数和低相关性入口始终可见；作者关注结果默认保留。手动忽略只隐藏显示，不删除记录，不自动取消其他任务下的发现关系。

### 2. 任务配置与检索语义

| 字段 | 类型及规则 |
| --- | --- |
| `task_id` | UUID，稳定标识，名称变化不更换 ID |
| 名称、开关、优先级 | 必填名称；开关只控制自动运行；优先级 1～5，1 最高 |
| 研究主题 | 用户自然语言描述，供相关性分析使用；不能单独声称已据此完成检索 |
| 检索词组 | 英文关键词或短语；每组为同义词 OR，组间默认 OR；高级模式可显式改为 AND |
| 关注作者 | 姓名及可选别名；作者分支与主题分支为 OR，不套用主题词或分类 |
| 分类 | 可选 arXiv 分类，仅约束主题分支；预览中展示实际作用范围 |
| 不关注方向 | 自然语言偏好，作为分析和排序依据；第一版不生成隐式服务端排除条件 |
| 采集频率 | 默认 24 小时，可设 6、12、24、48 小时；手动运行不改变已保存频率 |
| 最新窗口 | 默认最近 30 天，可设正整数天数 |
| 热门窗口 | 默认 12 个日历月，可调整；计算月末时夹取当月最后一天 |
| AI 设置 | 模块级选择既有服务 ID 与模型覆盖值；默认跟随该服务的模型，不改变阅读聊天的模型选择 |

至少填写主题检索词、分类或作者之一；纯自然语言主题在保存前需要补充可执行检索条件。模板预填英文词，用户可编辑。界面不要求用户自己编写 arXiv 查询语法，保存前提供实际查询和少量原始结果预览。预览和缓存共享来源限流。

主题查询将词组映射到 `ti`、`abs`，使用括号、引号转义和 URI 编码。作者查询使用 `au`，别名逐个 OR。多个分支独立分页并取并集，保存分支证据。按分类发现、按关键词发现和按作者发现均只承诺对已保存查询的覆盖，不承诺涵盖所有语义相关论文。

姓名检索可能返回同名作者。详情提供作者姓名、作者顺序、来源身份信息与机构线索；来源未提供机构时保持空值。第一版不按姓名推断唯一作者身份，也不以缺少机构为理由丢弃结果。

| 模板 | 优先级 | 建议英文检索词，默认 OR |
| --- | --- | --- |
| 视觉方法 | 1 | `object detection`、`semantic segmentation`、`instance segmentation`、`knowledge distillation` |
| 工业视觉 | 2 | `industrial anomaly detection`、`defect detection`、`surface defect`、`aircraft engine inspection` |
| 通用深度学习方法 | 3 | `deep learning`、`representation learning`、`self-supervised learning`、`foundation model` |
| 材料性能预测 | 4 | `materials property prediction`、`metal organic framework`、`machine learning materials`、`graph neural network materials` |
| 网络与边缘计算 | 5 | `deep reinforcement learning routing`、`edge intelligence`、`computation offloading`、`network optimization learning` |

模板是检索起点，不表示研究者所有当前课题。视觉知识蒸馏和材料预测分别有 [DMKD](https://arxiv.org/abs/2309.02719)、[MOF 研究](https://pubs.acs.org/doi/10.1021/acs.jcim.2c00092)作为依据；工业视觉与网络方向参见[学院介绍](https://cise.njtech.edu.cn/info/1063/1129.htm)。作者关注可填写 `Xili Wan` 并预览核对结果；不自动启用、不承诺完整收集作者全部著作。

修改关键词、组间逻辑、作者、分类、研究主题或不关注方向时递增 `query_revision`，保存规范化配置及其哈希。窗口天数/月数独立记录在运行范围中，不递增查询修订；扩大窗口可复用原覆盖并补缺口。名称、开关、窗口和运行频率变化不失效分析缓存。运行使用配置快照，不能在同一次分页中混用两个修订。

修订后旧发现记录仍保留，标明对应旧配置；当前默认列表只按当前修订的发现关系生成。历史记录可以查看。新配置重新建立两种窗口覆盖，旧分页断点不能直接复用。仅改变优先级不重新分析。

### 3. 外部接口与网络默认值

#### arXiv

使用 `https://export.arxiv.org/api/query`，以 `search_query`、`start`、`max_results`、`sortBy=submittedDate`、`sortOrder=descending` 获取 Atom。使用 XML 命名空间解析标题、作者、摘要、分类、ID、PDF 链接、DOI、journal reference、`published`、`updated` 和总量；HTTP 200 内的 Atom 错误条目也按失败处理。

`published` 是首次版本提交时间，`updated` 是返回版本的更新时间；热门窗口与最新窗口统一以首次提交时间判断。不能把新版本误计为新论文。来源返回较新的版本时更新元数据并标记版本变化，已入库文件不自动替换。

每页默认 100 条。热门回溯先按连续 7 个 UTC 自然日切片，最新发现按 UTC 自然日切片；数量超过 1,000 的片段先拆到日，再拆到小时和分钟。记录每个切片的边界、查询和分页进度。时间过滤使用 `submittedDate`，边界分钟可重叠并以稳定 ID 去重，避免秒级字段与分钟级过滤造成边界漏项。

整个模块对 arXiv API 串行请求，发起间隔至少 3 秒。相同查询与时间片在同一个来源更新周期优先命中已完成缓存，失败片段和显式重试除外。这些接口字段和速率约束来自 [API 手册](https://info.arxiv.org/help/api/user-manual.html)与[使用条款](https://info.arxiv.org/help/api/tou.html)。

不能把来源的查询结果上限当作已覆盖整个范围。切片仍超过可遍历上限时继续拆分；已到一分钟而仍不能完整遍历，记录 `source_limit`，展示受影响时间和查询，停止宣称该片段完成。空页、总数或排序异常必须核对响应，不能直接推进整段水位。

完成的覆盖要求：该配置下所有分支、所有切片的分页结果均持久化。多页总数漂移时重跑切片并去重；按同一日内重复 ID 数与总数进行检查，无法取得稳定结果则保持部分完成。进度中的总量为来源本次返回值，不作为永久固定总量。

新返回的 PDF 链接规范化为 HTTPS，验证为 arXiv 受信主机及合法论文 ID。下载默认串行，遵循[自动访问说明](https://info.arxiv.org/help/robots.html)，不爬取网页、不调用第三方全文链接、不加入账户登录流程。

#### Semantic Scholar

第一版拟选择 Semantic Scholar 作为唯一引用统计实现。它支持直接用 arXiv ID 批量匹配，减少按标题误匹配；不同时开发 OpenAlex 自动后备。

接口契约：`POST https://api.semanticscholar.org/graph/v1/paper/batch?fields=paperId,title,externalIds,citationCount`，请求体为 `{"ids":["ARXIV:2309.02719"]}`。一次默认 100 个 ID，逐项映射、验证数组长度与返回 `externalIds.ArXiv`。未命中为未知，返回不同 arXiv ID 视为身份不匹配，不能绑定；第一版不使用模糊标题匹配兜底。[官方批量接口](https://api.semanticscholar.org/api-docs/peer-review)

可选填写 API key，使用 `x-api-key` 请求头。无 key 可尝试公开接口，但共享限流不能解释为本应用可用配额；客户端默认全服务串行、每秒最多一次请求，并服从更严格的 `Retry-After`。[官方访问说明](https://webflow.semanticscholar.org/product/api)

新候选写入论文库后即进入统计队列，无需先下载 PDF；已有成功统计默认 7 天后刷新；近期新论文未收录时 24 小时后再尝试。新候选和到期刷新交替处理，各队列内按待处理时间排序，避免年度回溯把旧候选刷新长期挤在后面。失败不能阻止其他候选展示。停止任务后仍保留已获取的统计。

引用值只接受非负整数。只有明确返回 `citationCount: 0` 才显示零；null、未匹配、网络错误与授权错误均不能转换为零。成功获取过统计后刷新失败，保留上次成功值与日期并标为过期，另记最近失败；不把旧值改成零或清空。

引用量是该服务的累计统计，可能合并预印本和正式发表版本，不能称为最近 30 天新增引用量，也不能保证与其他平台计数一致。数据下降也保留服务实际新值，不强行单调增长。趋势榜不属于第一版。

#### 超时与失败

元数据与统计请求连接超时默认 10 秒，总时限 45 秒；PDF 下载总时限 5 分钟、无数据超时 30 秒。网络中断、429、503 等可重试失败最多连续重试 3 次，指数退避并加抖动，优先服从来源指定的等待时间；预算耗尽后保持待重试状态和下一次可运行时间。

配置错误、401/403、格式错误不进行无限重试。论文不因单个请求失败而删除。错误记录只包含任务、阶段、切片或论文 ID、状态分类和可操作提示，不写密钥、Authorization 或完整模型请求内容。

### 4. 两种时间窗口与断点

所有持久化时间使用 UTC ISO 8601 字符串，展示转换为本机时区。latest 初始窗口按运行开始时刻向前减 30 天；hot 初始窗口按运行开始时刻向前减 12 个日历月。查询切片的范围固定为运行快照，分页期间不随时钟改变。

| 通道 | 首次运行 | 后续运行 | 覆盖完成的含义 |
| --- | --- | --- | --- |
| `latest` | 当前时刻向前回溯配置天数，最近日期优先 | 从最近成功水位前 7 天到本次截止时间，补足应用关闭期间间隔；持续重扫最近 7 天以吸收延迟索引 | 所有该通道查询分支在范围内都完成持久化 |
| `hot` | 当前时刻向前回溯配置月数，最近日期优先、分批继续 | 继续未完成切片，并每日补入新日期；每 7 天复核当前热门窗口的历史元数据与统计队列 | 元数据回溯完成与引用统计覆盖分别计算 |

7 天重叠为延迟索引的设计缓冲，不能证明来源永不出现更迟的数据。用户可手动对指定窗口重新回溯。热门通道的周期复核分摊到多个会话，不挤占最新通道的新增发现。

每页在一个论文库事务内完成“规范化论文 upsert、任务发现关系、版本记录、分页断点”。事务提交后才前移该页；切片所有页提交后才更新覆盖记录。请求失败、取消、磁盘满、解析失败都不推进完成边界。

应用重开恢复未完成切片，从该切片 `start=0` 重扫并去重，避免动态结果改变后按旧 offset 跳过数据。已经完成的切片仍可复用，直到进入周期复核。局部失败只让对应切片保持待恢复，不重做整年历史。

同一任务的两个通道共享论文与分析，但独立维护覆盖和失败状态；30 天范围已被 hot 完整覆盖时可以复用其片段结果与缓存，仍需单独标记 latest 的覆盖证据。覆盖复用必须使用同一查询修订和实际时间范围。

不因窗口缩小或论文过了展示期限自动删除历史候选。热门默认视图根据当前窗口筛选；历史记录仍可查询。扩大窗口只补足缺失时间，改变查询时重新覆盖。

### 5. 排序、筛选与分析额度

引用次数、规则相关性、AI 相关性分开存储。第一版不引入一个混合热度分数，也不让模型生成引用数字。

| 列表与排序 | 确定规则 |
| --- | --- |
| 最新相关／相关性 | 有当前有效分析的候选按 AI 相关性分数降序；单独展示“待分析”，以确定性的规则匹配分数降序；各组同分按首次提交时间降序和 arXiv ID 升序 |
| 最新相关／最新 | 按首次提交时间降序和 arXiv ID 升序；分析状态不改变位置 |
| 近期高被引／引用 | 成功统计按累计次数降序，过期成功值可参与但须标记；同分按规则相关性、首次提交时间、arXiv ID；未知统计作为单独分组 |
| 近期高被引／相关性 | 与最新相关的相关性排序相同，使用热门时间窗口 |

多个当前任务匹配同一论文时，相关性取当前有效任务分析中的最高分，显示归属任务；每个任务的结果仍可展开。没有有效分析时，使用规则分组，不把缺失分析视为 0 分。

规则分数只用于待分析排序与队列调度：设检索词组数为 N，标题命中组数为 T，摘要命中组数为 A，则分数为 `round(100 * (2*T + A) / (3*N))`；同一组在各字段最多计一次。N 为 0 时分数为 0，另保留作者或分类发现标记，不据此隐藏。分类仅作检索范围，不声称是主题匹配证据。作者分支有“关注作者”标记，不因关键词分数为 0 而隐藏。规则分数是本地规则结果，不是相关性概率。

AI 相关性阈值默认 40/100，仅控制“低相关性”显示分组。关键词检索返回结果不被 AI 自动删除或拒绝下载；作者关注结果即使低分也默认保留，并展示分数。手动忽略记录跨刷新保持，仍可通过筛选恢复显示。

每日 100 的单位定义为“模块所有任务共享的自动论文分析作业”，正常情况下每篇一次请求可对多个发现任务给出分别的摘要相关性，并同时产生标题和摘要中文翻译。为约束实际调用，重试与拆分请求也各占一次，因此一天成功分析的不同论文可能少于 100 篇；设置和用量说明要写明这一口径。固定每日计量边界为 UTC 零点，界面显示下次重置的本地时间，避免系统时区改变导致重复重置。限额只控制模型分析，不限制发现和统计。

每次真正发起模型请求前，在事务中预占并记录一个额度；缓存命中不计。响应失败、超时、取消或结果无法解析仍占本次额度，因为可能已发生计费；自动重试每次重新占用。进程重启不能退款正在执行的请求。请求尚未发送的取消释放预占，并由状态与发起时间证明。

队列默认将 70% 自动分析机会用于最新窗口，30% 用于热门历史；不足时互相借用。各通道内按任务优先级 5:4:3:2:1 加权轮询，同一论文的多个任务合并，重合论文归属最高优先级任务计队列槽位。轮询位置跨批次持久化，防止低优先级长期饥饿。

用户手动“分析此篇”默认也使用剩余额度，不额外放宽；额度耗尽时允许提高每日设置，但不悄悄绕过限制。UI 显示今日已发起、剩余额度、待分析数量。额度是控制调用量的手段，不是货币预算，第一版不凭模型名称估算实际费用。

### 6. AI 请求与缓存契约

复用既有 `AiProvider`、`AiKeyRotator`、`LangchainAiConfig` 和 `LangchainAiRegistry.resolveByProtocol`。控制器读取配置与密钥轮转状态，模型工厂通过 `LangchainAiRegistry(null)` 构造无工具流水线，后台服务不持有页面 `WidgetRef`。采集 AI 服务在开始请求前校验所选服务存在、启用、模型非空和密钥可用；不在失败后静默切换服务或调用聊天入口的旧配置后备。

采集服务拥有独立 `CancelableLangchainRunner`，默认并发为 1；不启用工具调用，不修改阅读聊天历史。取消采集只取消本次采集流与对应模型资源。既有聊天取消不能停止采集。通过源流收集完整输出，提取回答部分后校验 JSON，不把思考输出或错误文字当有效分析。

项目当前 RPM 控制为聊天入口私有函数。实现时仅将限流器提取为共享、可原子预占的服务，使聊天与采集共用已有 `Prefs().aiRpm`；它只拥有配额，不拥有请求和取消。不能让两个入口各自取得完整 RPM 配额，也不能为本功能全面重写 AI 后备机制。

模型输入仅为原始标题、摘要、分类和用户主题、关键词组及不关注方向；不包含 PDF 全文，不让引用量影响相关性判断。主题为空时以显式关键词组作为相关性目标；只有作者或分类而没有主题/关键词的任务不请求相关性分数，可以仅翻译，不能由模型补造用户研究目标。论文内容以不可信数据段传入，系统提示明确不执行其中指令。模型不能改变采集状态、下载 URL 或调用书架工具。

规范结果使用版本化结构，示意如下；下面的省略文字仅说明字段，不是正式测试夹具。

```json
{
  "schema_version": 1,
  "title_zh": "标题中文翻译",
  "abstract_zh": "摘要中文翻译",
  "assessments": [
    {
      "task_id": "任务 UUID",
      "profile_hash": "任务语义哈希",
      "relevance_score": 82,
      "reason_zh": "与任务相关的摘要依据",
      "evidence": [
        {"field": "abstract", "quote": "原始摘要中的连续文本"}
      ]
    }
  ]
}
```

服务校验版本、字段类型、分数 0～100、任务集合与输入中需要相关性判断的任务一致、证据为标题或摘要的真实连续片段。纯翻译请求明确要求 `assessments: []`，不以空结果伪装相关性判断完成。证据匹配只归一化空白和换行，不模糊修正文本。不支持的版本、缺少任务、伪造引文或无效 JSON 均标为分析失败；保留原始候选，不写成功缓存。不要通过截断分数或补默认空数组伪装成功。

任务主题过多时按输入上下文预算拆为数个请求，每次均占额度。无法容纳的单篇长摘要不静默截断，标为 `input_too_large` 并提供原始资料。正常分析只解释摘要能够支持的相关性，不生成全文实验和局限结论。

缓存键由 `arxiv_id`、标题/摘要内容哈希、按任务 ID 排序的主题语义哈希集合、服务 ID/协议/URL/实际模型/推理配置的指纹、prompt 版本、结果版本组成；指纹不包含 API key。新加入任务可以请求缺失的任务判断，已有任务判断继续复用；缓存中的翻译可在相同正文内容下单独复用。

任务名、采集频率、优先级、引用量变化不重新分析。摘要、主题语义、实际模型或 prompt 变化使对应分析成为旧结果，允许查看但不能用于当前 AI 排序。重新分析按队列额度执行，不立即清空旧中文翻译。仅 arXiv 版本号变化而标题摘要不变时可复用摘要分析。

### 7. 持久化模型

新增本机库 `paper_collection.db`，存放在既有应用数据库目录；schema 初始版本 1。该文件不进入现有 WebDAV 主库同步，主库 `currentDbVersion` 保持 7。论文 DAO 自己持有数据库连接，不继承固定访问 `DBHelper` 的 `BaseDao`；不改造所有已有 DAO。

全局采集设置和任务保存在论文库；凭据不进入候选和运行记录。AI 只保存服务 ID 与模型覆盖值，读取既有凭据；可选 Semantic Scholar key 保存在本机偏好中，单独排除于偏好导出/导入，UI 仅掩码展示，HTTP 调试日志屏蔽该请求头。该存储沿用现有本机凭据能力，不声称新增加密保护。

| 表 | 字段与约束 |
| --- | --- |
| `paper_settings` | 单例：每日限额、计量日与已预占数、分析服务 ID/模型覆盖、分析轮询游标、配置版本 |
| `paper_tasks` | `task_id` PK；名称、enabled、priority、配置 JSON/版本、`query_revision`、创建/修改时间、下一次运行时间；状态枚举限制取值 |
| `papers` | `arxiv_id` PK（不含版本）；latest_version、标题、作者 JSON、原始摘要、分类 JSON、首次提交/版本更新时间、abs/pdf URL、DOI、journal reference、内容哈希、首次/最近发现、用户忽略状态 |
| `paper_task_matches` | `(task_id, query_revision, arxiv_id)` UNIQUE；分支与词句证据 JSON、首次/最近发现时间；task 和 paper 使用论文库内外键 |
| `paper_runs` | `run_id` PK；task、修订、触发原因、查询配置快照、范围、状态、阶段计数、开始/结束、失败分类、任务执行令牌 |
| `paper_scan_slices` | `(task_id, revision, channel, branch_hash, from_utc, to_utc)` UNIQUE；请求查询、start、总量、实际入库量、状态、最近检查时间、失败与重试时间 |
| `paper_analyses` | 内容/配置对应缓存键 UNIQUE；论文、实际模型指纹、prompt/result 版本、翻译、任务判断 JSON、状态、attempt、额度计量日、created_at、发起/完成时间、失败分类 |
| `paper_citations` | `arxiv_id` PK；provider、provider_paper_id、count 可空且非负、last_success_at、last_attempt_at、last_error、next_refresh_at；count 必须伴随成功时间 |
| `paper_imports` | `arxiv_id` UNIQUE；固定下载版本、请求 ID、状态、缓存相对路径、PDF MD5、可空 book_id、主库 file_path 快照、attempt、开始/完成时间、失败分类 |

作者、分类、任务配置、发现证据与模型结果的 JSON 均有结构版本，读取时校验。数据库外键在连接初始化显式开启。同一论文表保存最新元数据；已经入库的版本由导入表固定，足以区分“来源新版”与“当前阅读版本”，第一版不保存每个历史 PDF。

索引覆盖 `papers(published_at, arxiv_id)`、`paper_task_matches(task_id, query_revision, arxiv_id)`、`paper_scan_slices(status, next_retry_at)`、`paper_citations(next_refresh_at)`、`paper_analyses(status, created_at)` 与 `paper_imports(status)`。详情和列表使用分页查询；不得将一年候选全部载入内存后排序。AI 任务结果的索引化需求应由实际性能测试决定，第一版可在分析成功事务内同步写 match 的当前分数与缓存键，作为可重建投影。

成功 JSON 在事务中保存到分析缓存，再更新匹配关系投影；投影必须引用该缓存键、正文哈希和任务语义哈希。缓存是分析依据的唯一权威，投影失效后按待分析分组，不继续使用旧分数。

下载中间文件位于应用缓存的 `paper-collection/<request-id>/`，不可放入正式书籍目录参与同步。常规清缓存只影响未入库文件，恢复时检测文件缺失并重新下载；论文库、发现记录与额度记录不属于可清缓存。

### 8. 调度与生命周期

`PaperCollectionController` 为应用级、Windows 专用、keepAlive 的 Riverpod 所有者，论文页只是观察者。切换导航、进入阅读页或窗口最小化不停止采集；退出进程或用户暂停停止新工作。不会安装系统服务、计划任务或启动关闭后的定时执行。

初始化在路径、偏好、主库和阅读服务器就绪之后进行；PDF 入库还必须等待 Windows WebView 环境初始化完成。无任务时不启动来源请求。论文库初始化失败仅关闭该功能并显示错误，不阻止原有书架启动，也不自动重建损坏库。

一个应用级定时器检查到期任务，默认每分钟一次；到期任务合并执行，不为每个页面创建定时器。手动运行绕过频率等待，但不绕过来源限流、正在执行互斥或同查询缓存。相同任务运行中再次触发只返回当前运行 ID，不重复提交；不同任务按优先级轮询。

元数据采集、引用补充、AI 分析和下载/入库是独立队列。元数据不等待 AI；hot 队列不得阻断 latest；引用不可用不阻断下载。HTTP 客户端按来源限流，AI 默认 1 并发，PDF 默认 1 并发。正常情况下先运行 latest 的一页，再让 hot 运行一页，轮换推进。

| 对象 | 状态与恢复 |
| --- | --- |
| 任务运行 | `queued -> running -> succeeded / partial / failed / cancelled / interrupted`；succeeded 仅指该次计划的采集片段完成，界面同时显示独立的统计和分析进度 |
| 扫描片段 | `pending -> running -> completed / failed / interrupted`；失败重新扫描该片段，不影响完成片段 |
| 摘要分析 | `pending -> running -> succeeded / failed / interrupted`；额度不足保持 pending，并显示等额度；模型未配置显示 blocked |
| 下载入库 | `queued -> downloading -> downloaded -> importing -> imported`；各阶段可 failed/cancelled/interrupted，重新执行前先对账 |

暂停任务递增执行令牌、停止新请求并取消所属来源请求；任务正在进行的页只有在暂停前已提交事务才能记为完成，迟到响应不能继续推进旧运行。已提交候选保持不变。已经开始的书架入库不硬取消，等待其提交或失败以避免半成品。

暂停只停止该任务新发现与新分析；已经由用户勾选的下载/入库独立完成，除非用户取消下载队列。任务删除采用停用归档，保留发现依据和候选；第一版不自动删除论文或已入库书籍。

关闭窗口先停止定时器与新队列，取消 HTTP 和 AI，落盘中断状态；等待正在提交的入库排空，再关闭论文库、阅读服务器、WebView 环境与主库，最后关闭窗口。元数据解析延续既有 30 秒超时，文件保存与 DB 提交另行处理，不能用解析超时推断写入已经停止。正常关闭的排空检查期限默认 30 秒；期限到达仍有不可取消写入时保持窗口与共享资源，显示正在完成入库并允许重试退出，不与写入并发销毁资源。用户强制结束按下次启动对账恢复。

分析取消/超时后迟到输出不能写成功缓存，靠运行令牌与正文/配置哈希检查拒绝。进程重启把原 running 标为 interrupted；采集重扫未完成片段、AI 按额度规则恢复、下载检查临时文件、入库先检查主库是否已有对应 MD5。

### 9. PDF 下载与可等待入库

用户勾选时记录固定 arXiv 版本和请求 ID；下载期间即使来源更新，也不悄悄切换版本。文件名使用规范化 arXiv ID，旧式 ID 的 `/` 转义为安全文件名，不使用标题拼接路径。HTTP 请求和最终重定向主机必须仍在 arXiv 允许集合内。

响应必须是合法 PDF 内容，检查文件头与非空文件；不能只根据 `.pdf` 后缀或 HTTP 200 判断。默认自动下载单篇最大 100 MiB，超限保留候选并提示在来源页获取；这是下载保护，不是候选采集上限。下载失败不触碰主库；完整文件落盘后计算 MD5 并持久化 downloaded 状态。

新增 `PaperImportService` 适配现有导入机制。必要的共享改动为：`saveBook` 等待全部文件与数据库提交并返回 `Book`；`getBookMetadata` 用可完成一次的结果 future 等待元数据回调与保存结果；`importBook` 将该结果交给调用方。普通批量导入与封面重建仍可忽略返回值，但必须处理真实失败。

所有使用共享元数据 WebView 的调用，包括普通文件导入和封面重建，都通过同一个串行队列；只在论文服务串行不够。回调须等待保存，设置运行令牌，超时/取消后拒绝迟到保存；只在本次保存或释放失败处理结束后释放队列，不能用全局 WebView 置空作为成功标志。文件清理、封面保存失败与 DB 写入失败不能被误报为成功。

适配器在导入前查已记录的 paper-import 关联和主库 MD5。已存在活跃书籍时直接关联，不生成重复书籍、不替换阅读文件；已被软删除的书籍显示可恢复状态，不能误显示已在书架。主库 MD5 没有唯一约束：优先保留仍有效的原关联；否则查询全部匹配并优先活跃记录，多条活跃记录时让用户选择已有书籍，不能随机绑定或把软删除记录误认成唯一匹配。用户选择恢复时沿用既有书架恢复行为。没有找到匹配时进入既有元数据/封面流程，并用 arXiv 标题、作者、摘要作为缺失 PDF 元数据的备用值。

书架提交和论文关联是两个数据库的两步操作，不能宣称跨库原子事务。顺序为：记录 importing 与固定 MD5；主库导入成功返回 Book；论文库写 imported、book_id 和文件快照。进程在第二步后中断时，下次按 MD5找到 Book 并补关联，不再次下载或覆盖已有文件。

文档所述“可恢复状态”不是新增自动恢复规则。若现有恢复入口不能返回可等待结果，实现阶段须提供最小的显式恢复操作并验证笔记保持；不能仅按 `getBookByMd5` 非空就认为当前书架里已有活跃论文。

主库同步可能更换自增 ID。打开论文时先核验保存的 book_id 与 MD5；不一致则按 MD5重新绑定。没有相符书籍时显示未在书架，绝不能打开另一本恰好使用相同 ID 的书。已入库 PDF 的新 arXiv 版本只提示来源新版，第一版不自动替换或迁移标注。

### 10. 同步、存储路径与升级边界

主库同步和入库提交必须互斥。不能只检查某一时刻的 `isSyncing`：它在同步入口的部分网络步骤之后才置位，存在检查与写入间隙。实现一个范围明确的库操作锁，覆盖主库同步入口直到完成/失败、所有文件导入从查重至提交、以及会关闭主库的路径迁移；不将普通阅读查询长期纳入这把锁。

同步操作可以先在无锁状态完成不修改本地库的准备工作，但在确定方向和本地快照/替换前必须取得锁并重新校验相关状态；不得在 UI 已展示“已入库”之后再被并发下载的旧主库覆盖。同步等待时不阻塞论文原始元数据和统计队列，只阻塞进入主库的导入阶段。

自定义存储迁移前暂停全部采集、取消模型与网络流、排空导入、关闭论文库；主库也按迁移所有者的顺序关闭。目录包含论文库，但不能直接复制正在写入的 SQLite 文件。迁移成功后用新路径重新打开、复核 schema 和连接；失败恢复原路径与状态，不能在两个目录继续并行写入。迁移操作仅在用户已有存储迁移动作中执行。

| 数据与消费者 | 兼容性要求 |
| --- | --- |
| 原主库格式、书籍文件、笔记与进度 | 第一版保持主库 schema 7，不新增论文列；旧应用继续按已有格式读取 |
| 新论文库 | 仅新版采集模块读写；旧应用忽略该文件；不把库路径误加入 WebDAV 数据库版本发现 |
| 新配置 JSON | 版本 1，缺少可选字段在统一读取层使用本文默认值；无效必填和未知枚举阻止运行并提示修复 |
| 更高版本论文库 | 禁止降级写入，功能停用并提示需要兼容版本；不静默重建或清空 |
| 既有 AI 配置 | 只引用服务 ID 与可选模型覆盖，不更改已有序列化格式；服务删除使分析 blocked |
| 既有主库下载/覆盖 | 同步后按 MD5重新对账论文关联；无匹配时解除当前活动关联，保留原导入记录 |

创建独立库属于新增持久化格式；后续升级使用独立版本迁移。升级已有论文库前校验目标文件、user_version、表和数据约束，在关闭写入后生成一致快照并验证可打开及 schema；迁移失败不更新版本，不触碰主库。快照放应用恢复目录，显式管理保留，不散落 `.bak`。

实现开发只允许在隔离测试数据库验证初始化和迁移。运行安装应用导致真实库写入，应在单独的实际运行验证中明确目标与授权，不能以本设计批准替代对现有数据库操作的授权。本轮只检查源码与公共接口，没有访问或改写用户数据库。

1. 可等待的共享导入与库操作锁，验证原导入、失败、重复和同步排斥；这是安全入库的前置。
2. 论文库、单任务手动 arXiv 采集、原始详情和单篇下载入库，完成无 AI 的最小闭环。

4. Semantic Scholar 引用补充、未知与过期状态、热门排序和刷新。
5. 独立 AI 分析、缓存、额度与公平队列、中文翻译、相关性依据和筛选。
6. Windows 页面整合、批量入库、国际化、存储路径迁移、真实来源与 Windows 发布构建验收。

## Alternatives considered

| 方案 | 取舍 |
| --- | --- |
| 直接往书架主库增加论文表 | 主库版本和整库同步会影响所有设备，调度断点也会传播；独立本机库更符合第一版 Windows 与本机运行范围 |
| 用 SharedPreferences 存整个候选列表 | 年度回溯需要分页、索引、事务断点和原子额度，偏好键不能承担这些查询与一致性要求 |
| 所有候选先 AI 筛掉再展示 | 与减少漏检、每日额度和失败继续展示冲突；先保存候选，分析仅排序和分组 |
| 仅采集最近 30 天后排序热门 | 不能提供首次覆盖 12 个月的热门结果；独立回溯并共享记录 |
| 使用单一混合相关性热度分数 | 无法解释新论文低引用、统计未知和高被引低相关的差异；保留独立排序 |
| 直接复用聊天 `aiGenerateStream` | 全局取消实例和错误字符串不适合后台结构化分析；复用配置、模型工厂与 RPM，运行实例独立 |
| 同时接 OpenAlex 与 Semantic Scholar 自动后备 | 增加匹配和统计口径切换成本；先以精确 arXiv ID 的一个服务完成，失败保留未知 |
| 自建服务器、系统定时任务或网页爬虫 | 当前需求是在应用运行时采集公开 arXiv，不需要新增部署、桌面自动化或网站适配 |

## Risks

| 风险 | 可见影响与控制 |
| --- | --- |
| 宽泛主题的年度结果很多 | 分批落库、分页展示、进度可见；不把 AI 额度、页面条数或服务上限当作已采集全部 |
| arXiv 延迟索引、分页变化、来源上限 | 重叠窗口、恢复重扫、热门周期复核；无法确认的时间片保持未完成，覆盖说明限定为实际查询 |
| 高被引仍可能不相关 | 独立展示相关性，可切换排序；资料和证据供人工判断，不用引用量替代研究质量 |
| 新论文未被引文服务收录 | 未知单列并重试，不解释为零或失败论文 |
| AI 判错、伪造证据或任务摘要注入 | 校验摘要片段、按不可信数据处理、关闭工具；模型结果不决定删除与下载权限 |
| 共享导入和同步互斥改动影响已有功能 | 必须先验证原有入口与失败路径；跨库提交靠 MD5 对账，不能只加论文页测试 |
| 本机采集数据不参与既有同步 | 跨设备可读已入库 PDF，但不能看到候选/任务/排序依据；设置中明确说明，不承诺跨设备完整论文工作流 |
| 额度只是次数控制 | 每次请求仍可能费用不同；失败已发出的请求也占额度，展示实际发起数，不承诺货币封顶 |
| 清缓存或切换存储位置 | 未入库下载可重取；采集库不放缓存；迁移须停写并重开连接 |

第一版不会评估全文结论、自动替换已阅读 PDF、抓取非公开全文、建立作者身份库或宣称引用变化趋势。已入库论文的阅读体验由现有 PDF 阅读链路承担。

## Rollback

设计阶段只有文档新增，无应用包、主库、论文库或外部账号变更需要回滚。

实现后回退应用前先停止采集、取消网络与 AI、等待当前入库提交、关闭相关连接。旧应用继续使用 schema 7 主库和现有 PDF；保留独立论文库，旧应用不读取它，不做删除或自动降级。重新安装兼容新版后应能够恢复候选和任务，running 状态按中断恢复。

入库已经成功的书籍、笔记和进度是用户数据，回退功能不撤销它们。两库关联未提交的记录通过 MD5 对账；不得为消除论文记录而删除主库书籍。若共享导入或库操作锁验收失败，修复后再发布，不能靠放宽状态检查或清空记录绕过。

未来论文库迁移失败时，保留失败库和一致恢复快照，停用采集并检查迁移版本与完整性；确认目标与恢复方案后再恢复。恢复会丢失快照之后的采集状态，须明确范围。主库同步、路径迁移和用户已有数据库的恢复由其各自所有者处理，不能把本提案视为执行恢复的授权。
